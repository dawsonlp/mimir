# Mimir v5.5.0 Release Notes - Change Outbox

## Status

Planned release notes for CR-1 handoff and release.

## Summary

Mimir now includes a transactional change outbox for committed substrate writes.
The outbox provides a durable Mimir-owned replay ledger, while Kafka provides
live delivery to external projection consumers.

## What Changed

- Added `mimirdata.change_outbox`.
- Added compact versioned change events for artifact, relation, and embedding
  creates.
- Refactored create paths so domain row, provenance row, and outbox row commit
  in one transaction.
- Added `python -m mimir.outbox_publisher`.
- Added Kafka publisher configuration:
  - `KAFKA_BOOTSTRAP_SERVERS`
  - `MIMIR_CHANGE_TOPIC`
  - `OUTBOX_BATCH_SIZE`
  - `OUTBOX_POLL_INTERVAL_SECONDS`
  - `OUTBOX_RETRY_BASE_SECONDS`
  - `OUTBOX_RETRY_MAX_SECONDS`
- Added `confluent-kafka` for producer-only Kafka delivery.

## Delivery Semantics

- Kafka delivery is at least once.
- Duplicate delivery is possible.
- Consumers must deduplicate by `event_id`.
- Consumers should treat outbox `sequence` as the replay cursor.
- `published_at` is set only after Kafka acknowledgement.
- Published outbox rows remain retained by default.

## Replay Semantics

The durable replay source is Mimir's `change_outbox`, not Kafka alone.

Kafka topic retention may be finite in larnet. Consumers that need rebuild
guarantees beyond Kafka retention must use a Mimir backfill/replay path once
that surface is exposed, or coordinate a publisher replay from retained outbox
rows.

## Kafka Client Note

Mimir uses `confluent-kafka` for producer-only publisher delivery in this
release. This is acceptable for the current publisher because it does not
consume Kafka or advance Kafka offsets.

Do not accept Confluent consumer defaults without use-case analysis. For
event-log or projection-rebuild consumers, automatic offset movement can violate
replay expectations. Any Mimir-owned or Efforts-owned consumer should explicitly
configure offset policy and commit offsets only after durable processing.

## larnet Handoff

larnet should add a publisher service using the Mimir API image:

```text
python -m mimir.outbox_publisher
```

Required environment:

- `DATABASE_URL`
- `POSTGRES_PASSWORD`
- `KAFKA_BOOTSTRAP_SERVERS`
- `MIMIR_CHANGE_TOPIC=mimir.changes.v1`

larnet should document topic retention for `mimir.changes.v1` and avoid
describing Kafka retention as Mimir's durable replay guarantee.

## Efforts Handoff

Efforts should:

- consume `mimir.changes.v1`;
- deduplicate by `event_id`;
- order or resume by `sequence`;
- expect compact payloads and fetch full Mimir entities when needed;
- explicitly configure Kafka consumer offset behavior for replay semantics.

## Validation Before Release

- Backend unit tests pass.
- Docker image builds.
- Publisher module imports in the built image.
- Local runtime smoke verifies:
  - migration creates `change_outbox`;
  - API create writes an outbox row;
  - publisher sends a Kafka message;
  - publisher sets `published_at` after acknowledgement.
